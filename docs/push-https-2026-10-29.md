# HTTPS и Web Push — подготовка завершена 29 октября 2026

Код подготовлен и проверен локально. На печи этот этап не развёрнут и уведомления
не активированы: пользователь подтвердил отсутствие домена и отложил выбор HTTPS.
На обеих Raspberry остаётся установленная мобильная версия от 28 октября.
Версия проекта остаётся 3.2.7, коммит и пуш не выполнялись.

## Что реализовано

- Необязательный второй HTTPS-вход к тому же приложению. Существующий HTTP
  сохраняется для встроенного Electron и текущего обмена между печами.
- Web Push через стандартные Push API/Service Worker и web-push 3.6.7.
  Иконка сохранена из старого приложения. Нет обработчика fetch, офлайн-кэша API,
  отложенных команд или команд управления внутри уведомлений.
- События запуска, завершения отдельного цикла, окончания профиля, остановки,
  программной ошибки и потери связи Raspberry с платой. Завершение сообщает,
  выполнен ли профиль в допуске. Нажатие уведомления открывает панель печи.
- На телефоне: «Ещё» → «Уведомления». На ПК — в настройках. Каждый телефон
  выбирает свои события, вводит PIN 3457 и самостоятельно разрешает уведомления
  в системном запросе. Есть сохранение событий, тест и отключение.
- VAPID-ключи и максимум 32 подписки хранятся в `config.json` как конфигурация.
  Закрытый ключ и список адресов подписок не возвращаются публичным API.
  Новые записи конфигурации создаются с правами 0600. События не пишутся на SD
  и не образуют дополнительную историю: используется только ограниченная
  очередь доставки (64 события) в ходе работы, без сохранения и повтора после
  перезапуска. События старше пяти минут отбрасываются; TTL доставки 300 секунд.
- Ошибки доставки изолированы от регулирования. Отправка асинхронная, до четырёх
  запросов одновременно и с таймаутом 5 секунд. Автоматических повторов нет;
  404/410 удаляют просроченную подписку, временные ошибки сохраняют настройки.
- Подписки принимаются только с настроенного HTTPS-origin, с PIN и для известных
  push-служб Apple, Google и Mozilla. Произвольные URL, HTTP, нестандартные порты,
  учётные данные в URL и некорректные ключи отклоняются. Нет CORS-разрешения
  для посторонних сайтов. Конфигурация одного телефона не открывает настройки
  печи или управление нагревом.

Уведомления не подтверждают физическую исправность печи и могут задерживаться,
отключаться режимами телефона или не доставляться при отсутствии интернета.
Аварийная защита, звук и автономное выполнение профиля от них не зависят.
При полном отключении Raspberry она сама уже не сможет отправить событие;
уведомление об этом потребовало бы отдельного внешнего наблюдателя.

## Что потребуется для включения

1. Выбрать стабильное HTTPS-имя для каждой печи и способ выдачи доверенного
   сертификата. Имя должно открываться с телефона в нужной сети. Самоподписанный
   сертификат с предупреждением браузера не считать готовым решением.
2. Выбрать контактный адрес VAPID (email либо HTTPS URL).
3. Обновить сервер с установкой производственных зависимостей из lockfile
   на Raspberry (`pnpm install --prod --frozen-lockfile` с соответствующим Node
   24/pnpm 11.25.0), установить сборку server и pc-dist. Одного копирования dist
   недостаточно: появилась зависимость web-push. Не пересобирать/перезаписывать
   встроенный интерфейс Electron. Перед перезапуском — простой печи и резервная
   копия текущей программы на USB.
4. Настроить .env, пример ниже. Альтернатива прямому TLS — локальный reverse
   proxy на Raspberry. Express доверяет заголовку протокола только loopback;
   прокси должен сам задавать X-Forwarded-Proto и не передавать значение клиента.
5. Открыть именно HTTPS-адрес, на iPhone добавить на экран «Домой» и открыть
   оттуда. Разрешить уведомления по нажатию, ввести PIN и выбрать события.
6. Проверить тестовое уведомление, затем события на наблюдаемой печи,
   сворачивание, блокировку экрана и работу телефона вне Wi-Fi. Для открытия
   локальной панели по уведомлению телефон должен иметь доступ к сети печи;
   сама push-доставка идёт через интернет-службу браузера.

```dotenv
# Примеры, не реальные адреса или сертификаты:
MERCURY_PUBLIC_URL=https://oven.example:8443
MERCURY_PUSH_SUBJECT=mailto:service@example.org
MERCURY_HTTPS_PORT=8443
MERCURY_TLS_CERT_PATH=/home/pi/.config/mercury-v3/tls/fullchain.pem
MERCURY_TLS_KEY_PATH=/home/pi/.config/mercury-v3/tls/privkey.pem
```

При внешнем TLS-прокси последние три переменные можно не задавать. Не публиковать
обычный HTTP API печи в интернет ради уведомлений. Для push-доставки не нужны
входящие интернет-подключения к Raspberry; нужны исходящие HTTPS-подключения
к push-службам и интернет у телефона. Доступность самой панели вне LAN — отдельный
вопрос сети/VPN, не решённый выдачей сертификата.

## Проверки

- Сервер и браузерная сборка проходят TypeScript/build.
- Полный прогон: 132 успешно, 0 ошибок, 1 Linux-тест выключения пропущен на Windows;
  `test-results/push-https-2026-10-29.txt`.
- Цикл виртуальной платы проверяет реальные уведомительные события
  started → cycleCompleted → completed и started → stopped при перезапуске.
- Проверены раздельные телефоны, выбор событий, PIN/HTTPS-origin, отказ
  произвольным адресам, шифрование aes128gcm/VAPID, удаление 410-подписки,
  сохранение подписки при 503, отмена очередной доставки после отписки.
- HTTPS проверен с отдельным localhost-сертификатом, которому доверяет только
  тестовый HTTPS-запрос через параметр ca. Тестовые ключи не установлены на печи
  или телефоны и не предназначены для эксплуатации.
- Service worker показывает текст уведомления и по нажатию открывает только
  корень печи; адрес из payload не используется для внешнего перехода.
- Браузерный макет показывает выключенные кнопки и причину «Не настроен HTTPS».
  Доставка настоящему iPhone/Android не заявляется проверенной до выбора HTTPS.

Первичные источники реализации: https://github.com/web-push-libs/web-push и
https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/.
