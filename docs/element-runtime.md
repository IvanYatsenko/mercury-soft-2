# Учёт наработки элементов

Файл на Raspberry: `/media/flash/mercury-logs/element-runtime.json`.
Корень USB задаётся существующей переменной `MERCURY_LOG_USB_MOUNT`.

Содержит версию формата, дату начала учёта, время последнего сохранения и
`configurations`. Ключ конфигурации: модель, выбранное питание и тип платы,
например `M300-380V-380V`. В `onSeconds` накапливаются секунды включения:
`topHeater`, `bottomHeater`, `infrared`, `infrared2`, `infrared3` (если есть),
`convection`, `f1`, `f2`. Лампы учитываются парами. У М300 с параллельными
вентиляторами значения f1/f2 одинаковы, поскольку они включаются одним выходом.

Источник — успешные команды setHV и прочитанные состояния выходов. Это
оценка времени включения, а не измерение тока или подтверждение исправности
нагрузки. Профиль, поддержание, охлаждение и проверка элементов охвачены
одним перехватчиком обмена. Симулятор не увеличивает реальные счётчики.

Запись идёт в отдельном worker, атомарной заменой JSON с fsync примерно
каждые 10 секунд и при штатном завершении сервера. При внезапном отключении
может потеряться последний несохранённый интервал. После перезапуска счётчики
продолжаются с файла; время выключенного приложения не прибавляется.

Нет USB — нет файла и накопления для последующего воспроизведения.
Повреждённый JSON не обнуляется и не перезаписывается. После ошибки файловой
системы учёт отключается до перезапуска сервера. Неизвестное состояние и
разрывы наблюдений свыше 5 секунд не засчитываются. Ошибка записи не влияет
на управление печью; зависший worker отключается ограниченным таймаутом.
Файл не входит в удаляемые архивы фоновой очистки USB 80%→50%.

Учёт начинается после установки этой функции; старая история автоматически
не пересчитывается. Никакие счётчики не пишутся на SD-карту и не выводятся
в интерфейс пользователя.

Установлено на М300 (10.10.1.88) и М400 (10.10.1.13) 28.10.2026.
На обеих USB подтверждено создание файла и увеличение времени конвекции
при нулевых счётчиках выключенного нагрева. Electron и профили сохранены.
