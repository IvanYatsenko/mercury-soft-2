# Раздельный доступ, PIN и мобильные экраны

Все экземпляры интерфейса получают независимый случайный идентификатор, передаваемый только своей печи в `X-Mercury-Client`. Сервер хранит разрешения отдельно. Разблокировка/блокировка Raspberry, ПК, телефона или другой вкладки не меняет доступ остальных. Обновление страницы создаёт новый заблокированный экземпляр. Перезапуск сервера и изменение PIN отзывают все разрешения.

PIN оператора (исходно 3457) меняется в общих настройках с вводом текущего и подтверждением нового. Допустимы 4–5 цифр, расширенный <PIN> зарезервирован. На диске хранится scrypt-хеш с солью, публичные API его не возвращают. Запуск веб-профиля принимает текущий PIN либо расширенный.

Восстановление доступно только локальному Electron, с учётом реального адреса за доверенным обратным прокси. На экране печи открыть ввод PIN, нажать штатную физическую кнопку выключения, дождаться отсчёта и в течение 15 секунд ввести 88888888. PIN возвращается к 3457, выполняется один сигнал 700 мс и продолжается штатное выключение. Без кода — выключение после истечения окна. Ввод до физического события, с другого клиента, через браузер или повторное использование отклоняются. До окончания окна процесс приложения остаётся запущен; остальные команды при выключении заблокированы. Прошивка получает задержку отключения питания перед ожиданием ввода. Аварийное выключение не подменяется восстановлением.

На мобильной главной действия процесса находятся под графиком; после ввода PIN в верхней панели появляется ключ блокировки. В списке истории нет «Назад», в деталях кнопка сохранена. Мобильные настройки оповещений перенесены в «Ещё»; удалены вложенное окно, общая информационная плашка, настройки/блокировка/тема и сведения о HTTPS из этого меню. На ПК прежнее расположение оповещений сохранено. Проверка совместимости и передача копии профиля не требуют PIN получателя; проверка параметров, подтверждение предупреждений и запрет передачи занятому получателю сохранены.

По расширенному PIN доступна кнопка сброса моточасов с подтверждением. Сброс требует исправного USB и остановленного процесса, обнуляет счётчики USB и резервную копию. Самостоятельно счётчики не сбрасываются.

`element-runtime-backup.json` рядом с `config.json` получает копию USB-счётчиков один раз за загрузку ОС (по Linux boot ID), а также при явном сбросе. При отказе USB резервная копия используется только для отображения: ни на SD, ни в RAM новая наработка не накапливается. История запусков и технические логи по-прежнему пишутся только на USB.

Проверки: полный прогон 151 успешно / 1 пропуск Linux-теста на Windows; дополнительные тесты локального восстановления, блокировки при выключении и прокси прошли. Проверены независимые клиентские идентификаторы, изменение хеша PIN, отзыв доступа, тайм-аут и одноразовость восстановления, длинный сигнал на виртуальной плате с сохранением остальных выходов, резервирование по boot ID и сброс счётчиков. Мобильные экраны и ПК проверены на макете без нагрева. Реальное выключение и реальный сброс PIN/моточасов автоматически не запускались — нужна отдельная физическая проверка пользователем.

Установлено на 10.10.1.88 и 10.10.1.13. Обе платы готовы, нагрев выключен. Проверка двух независимых тестовых клиентов на каждой печи подтвердила раздельные обычные/расширенные разрешения и блокировку чтения моточасов для другого клиента. Источник моточасов — USB. Файл `/home/pi/.config/mercury-v3/element-runtime-backup.json` существует на обеих печах и соответствует текущему boot ID. Тестовые разрешения закрыты после проверки; пользовательские сессии не использовались. Настройки и профили сохранены.
