# Первый этап общего обзора печей — 28 октября 2026

Реализованы страница «Печи в сети», обнаружение mDNS/DNS-SD через Avahi,
ручное добавление IPv4-адреса и переход на интерфейс выбранной печи.
Список показывает модель и питание, описание, температуру, состояние платы,
текущий профиль, оставшееся время и время последнего успешного обновления.

## Обнаружение и ограничения

На каждой Raspberry установлены `avahi-utils`, работает `avahi-daemon`.
Сервер запускает `avahi-publish-service` и `avahi-browse` для `_mercury._tcp`.
Клиентские утилиты не требуют root при работе сервера. Завершение сервера
останавливает дочерние процессы. При ошибке утилиты повторно запускаются;
интерфейс объясняет недоступность автообнаружения и предлагает ручной путь.
Формат утилиты сверялся с [исходниками Avahi](https://github.com/avahi/avahi/blob/master/avahi-utils/avahi-browse.c).

Нет перебора адресов подсети. Обрабатываются только объявления сервиса Mercury
для IPv4 и порта 3001; ручной адрес должен принадлежать частной IPv4-подсети
одного из локальных интерфейсов. Сетевой и широковещательный адреса исключены.
Перед сохранением ручного адреса сервер проверяет `/api/device`, запрещает
перенаправления, ограничивает время и размер ответа. До четырёх параллельных
проверок, не более 32 сохранённых вручную адресов и 64 записей каталога.

Опрос состояния выполняет сервер каждые 10 секунд, браузер читает каталог
каждые 5 секунд. При ошибке сохраняется последнее время успешного ответа,
данные явно помечаются устаревшими, температура скрывается, переход отключается.
Отдельно показаны недоступность Raspberry и потеря связи с платой.
Обнаружение читает состояние и не отправляет команды нагрева.

Постоянный идентификатор не добавлен: записи объединяются по IP. После смены
IP старая запись может оставаться недоступной, новая обнаруживается отдельно.
Арбитраж управления несколькими клиентами не реализован. Кнопка перехода
открывает выбранную печь напрямую, без переноса PIN-доступа другой печи.

## Название и описание

В настройках ПК после PIN **<PIN>** доступна карточка «Название и описание этой
печи». Данные хранятся именно на Raspberry в её `config.json`: `ovenName`
(до 64 символов) и `ovenDescription` (до 240). Пустое название означает имя
модели. Они доступны через API и видны соседним печам. Поля не меняют модель,
питание, калибровки или профиль. Изменение описания не требует остановки нагрева.

Ручные адреса сохраняются в `knownOvenAddresses`; изменение списка требует
обычного или расширенного PIN. Сами обнаружение и чтение описаний публичны
в локальной сети. Текст отображается React как текст, без HTML.

Замороженный интерфейс Electron не менялся. Поля доступны в веб-настройках
сервера Raspberry; добавление полей на локальный экран остаётся отдельным
согласованием, поскольку пользователь зафиксировал Electron.

## API

- `GET /api/device` — ограниченные сведения об этой печи, без истории USB.
- `GET /api/fleet` — текущий каталог печей и состояние обнаружения.
- `POST /api/settings/fleet` с `{ "address": "10.10.1.13" }` — проверка и сохранение
  ручного адреса; `DELETE /api/settings/fleet/:address` — убрать ручную запись.
  Обнаруженная автоматически карточка при этом остаётся.
- `GET /api/settings/oven-identity` — название и описание.
- `PUT /api/settings/oven-identity` с `{ "name": "...", "description": "..." }` —
  сохранить метаданные с PIN <PIN>.
