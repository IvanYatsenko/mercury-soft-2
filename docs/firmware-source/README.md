# Исходники прошивки контроллера

Эта папка содержит копию исходного кода и настроек проекта IAR из `mercury-fw-3xx`.
Файлы сохранены для изучения протокола и поведения платы; этот каталог не входит
в сборку серверного приложения. Файл `состояние.docx` также скопирован из источника.

## Состав

- `source/` — исходники C/C++ контроллера и заголовочные файлы.
- `project/` — файлы проекта IAR и конфигурация линкера.
- `состояние.docx` — сопроводительный документ из папки прошивки.

Скомпилированный `Debug/Exe/tmeter.hex`, библиотеки, даташиты и прочие справочные
материалы не копировались. Оригинальный каталог не изменялся.

## Протокол ITMP, найденный в `source/main.cpp`

Плата STM32 использует ITMP через USART2/RS485: скорость 115200, адрес по умолчанию 2. В таблице прошивки экспортированы команды:

| Команда    | Вход                                        | Ответ / эффект                                                                                                           |
| ---------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `stat`     | целое число с битовой маской                | Сбрасывает указанные флаги ошибок; при `STARTING` переводит плату в `WORKING` и включает сигнальную лампу.               |
| `poweroff` | задержка в секундах; без аргумента — 500 мс | Записывает задержку выключения и возвращает текущее состояние. Сам обработчик команды не выключает плату немедленно.     |
| `get`      | —                                           | `[температура CPU, T1, T2, частота вентилятора 1, вход датчика/двери]`.                                                  |
| `gett`     | —                                           | Как `get`, но пятый элемент — `globalstate`.                                                                             |
| `setHV`    | до 8 значений                               | Управляет высоковольтными выходами; запрещён, если плата не `WORKING` или есть ошибки аварийной остановки/прочая ошибка. |
| `setLV`    | до 6 значений                               | Управляет низковольтными выходами.                                                                                       |
| `fansfreq` | —                                           | Возвращает частоту двух вентиляторов.                                                                                    |
| `sensors`  | —                                           | Возвращает состояния двух цифровых входов.                                                                               |

Основные значения `globalstate`: `WORKING=1`, `ITMP_NO_CMD_TIMEOUT=2`, ошибки датчиков/
перегрева/кнопки/аварийной остановки — `4..128`, `STARTING=256`,
`SHUTDOWN_AFTER_RELEASE=1024`. Команда `stat [2]` снимает именно флаг
`ITMP_NO_CMD_TIMEOUT`; если до этого плата находилась в `STARTING`, она становится
`WORKING`.

В прошивке таймаут отсутствия ITMP-команд равен 3 секундам. Ожидание `STARTING`
ограничено `OnTimeoutMs=120000` (2 минуты). В коде также есть задержка зуммера 100
секунд при физическом нажатии кнопки; это отдельная логика кнопки, а не таймаут ITMP.

## Виртуальная плата

При `pnpm dev` сервер запускается с `MERCURY_CONTROLLER_MODE=simulation`. Виртуальная
плата эмулирует перечисленные команды, начальное состояние `STARTING`, переход
`stat [2]`, показания датчиков и выключение с задержкой из `poweroff`. Снимок доступен
по адресу `GET http://127.0.0.1:3001/api/controller/virtual-board`. Для второго
экземпляра сервера можно задать `MERCURY_API_PORT`.

Это модель программного протокола для разработки интерфейса. Она не проверяет
электрические сигналы, физическую кнопку, аварийный стоп, термопары или реальную
работу силовых выходов; задержка завершения выключения в симуляторе моделирует
наблюдаемый итог, тогда как исходная команда `poweroff` только устанавливает таймер.
