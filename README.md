# Mercury

Учебный проект управления печью оплавления. Развиваем небольшими шагами:
задача → самостоятельная реализация → ревью → проверка.

## Что есть сейчас

- `apps/web` — браузерный клиент: React, TypeScript, MUI, Vite.
- `apps/desktop` — Electron + TypeScript для встроенного экрана печи; использует тот же React-интерфейс.
- `apps/server` — Node.js + TypeScript, единственный маршрут `GET /api/health`.
- MobX установлен; первый store добавим, когда появится состояние приложения.
- Строгая проверка TypeScript, Prettier, единый lockfile.

Это стартовый шаблон: он не подключается к плате и не управляет нагревом.

## Запуск

Нужны Node.js 24 LTS и pnpm 11.25.0. Если pnpm отсутствует:

```sh
npm install --global pnpm@11.25.0
```

Из корня проекта:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

`pnpm dev` запускает сервер, Vite и окно Electron. Electron ждёт готовности обоих серверов
(до 60 секунд). Закрытие окна останавливает остальные процессы на Windows/Linux.
На macOS заверши приложение через Quit. Ctrl+C также останавливает всю группу.

Открыть в браузере http://127.0.0.1:5173. API: http://127.0.0.1:3001/api/health.
Vite перенаправляет `/api` на сервер. Оба процесса пока слушают только localhost.
`pnpm dev:web` запускает только сервер и браузерный интерфейс — для клиента ПК.
React обновляется автоматически; после изменений основного процесса Electron перезапусти `pnpm dev`.

## Запуск собранной версии

```sh
pnpm build
pnpm start
```

Сервер отдаёт собранный React-интерфейс и API на http://127.0.0.1:3001.
Electron открывает этот адрес; его можно открыть и в браузере.
Это локальный запуск сборки, не установщик и не готовое развёртывание на Raspberry Pi.
Для него позже отдельно настроим автозапуск сервиса, kiosk-режим и сборку под ARM.
Интерфейс Electron работает с изоляцией контекста, sandbox и без доступа к Node.js.
Preload/IPC пока не нужны: клиент обращается к серверу по HTTP.

## Проверки

```sh
pnpm typecheck
pnpm format:check
pnpm build
```

`pnpm check` выполняет все три проверки. `pnpm format` форматирует файлы.
Сборка создаёт `dist` внутри каждого приложения; эти файлы не коммитятся.
`pnpm --filter @mercury/server start` запускает собранный API.
`pnpm --filter @mercury/web preview` показывает собранный UI, но не проксирует API:
для совместного запуска при разработке используй `pnpm dev`.

## Направление развития

Node.js-сервис на Raspberry Pi будет работать с контрольной платой и хранить данные.
ПК подключается по IP через браузер: Electron на ПК не нужен.
Локальный экран печи использует Electron, мобильный клиент позже получит React Native.
REST API обслуживает запросы и команды; события состояния добавим отдельно.
Базу данных и мобильное приложение подключим на соответствующих учебных этапах.

## Ближайшее задание

Описать точку температурного профиля и профиль на TypeScript, затем написать
проверки чисел и порядка времени. Готовой реализации в шаблоне нет.

Старая версия используется только как справочный материал по оборудованию;
перенос её архитектуры не планируется.
