# Mercury 3.2.7

ПО управления печами оплавления **Меркурий-300** и **Меркурий-400**.
Основная платформа — Raspberry Pi с сенсорным экраном: сервер управляет платой
печи, Electron показывает интерфейс встроенного экрана. Отдельная панель ПК
доступна в браузере по IP-адресу Raspberry в локальной сети.

Версия **3.2.7** развивает отдельную панель ПК: обзор, таблицу профилей,
редактор с предпросмотром и настройки по PIN. Electron на печах зафиксирован
на **3.1.6**. Браузерная сборка создаётся командой
`pnpm --filter @mercury/web build:pc` в `apps/web/pc-dist`; сервер выбирает её
для обычного браузера, сохраняя прежние файлы `apps/web/dist` для Electron.

## Возможности

- Создание, редактирование и выполнение температурных профилей, выбор датчика
  камеры или датчика на плате, до 20 циклов выполнения.
- График заданной и фактической температуры, пауза, продолжение и остановка.
  Выполнение идёт на сервере и не зависит от открытой страницы.
- Совместное регулирование ламп и ТЭНов, прогноз температуры и управление
  охлаждением. Характеристики разделены для четырёх сочетаний: М300/230 В,
  М300/380 В, М400/230 В, М400/380 В.
- Поддержание 100 °C, индикация двери, элементов печи и связи с платой.
- При открытии двери во время профиля нагрев отключается и звучит предупреждение;
  после закрытия управление продолжается с попыткой догнать график.
- Два длинных сигнала при завершении в допуске ±4 °C, три — при выходе за допуск.
- Проверка элементов печи, настройка вентилятора, звуков и термозащиты.
- Подключение к Wi-Fi через NetworkManager на Raspberry Pi.
- История запусков и технический журнал только на исправном USB-накопителе.
- Виртуальная плата для разработки без оборудования.

На дисплее температуры округляются до целых; управление использует точные
значения. Выделение текста интерфейса отключено, поля ввода остаются редактируемыми.
После ошибки или перезапуска нагрев автоматически не возобновляется.

## Разработка и запуск

Нужны **Node.js 24** и **pnpm 11.25.0**. Команды выполняются из корня проекта.
Если pnpm не установлен: `npm install --global pnpm@11.25.0`.

Создай `.env` из [.env.example](.env.example):

```sh
cp .env.example .env
pnpm install --frozen-lockfile
pnpm dev
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.
`pnpm dev` запускает API, Vite и Electron. Для разработки только через браузер:

```sh
pnpm dev:web
```

Адреса по умолчанию:

- интерфейс разработки — `http://127.0.0.1:5173`;
- API — `http://127.0.0.1:3001/api/health`.

Vite перенаправляет `/api` на сервер. `Ctrl+C` останавливает группу процессов.
После изменения `.env` нужен перезапуск. `.env` не хранится в Git.

Для собранной версии:

```sh
pnpm build
pnpm start
```

Сервер отдаёт интерфейс и API на одном порту, по умолчанию `3001`.
Для запуска без Electron: `pnpm --filter @mercury/server start`.
Обычный `vite preview` не заменяет API-сервер.

## Конфигурация

| Переменная `.env`                    | Назначение                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------- |
| `MERCURY_CONTROLLER_MODE`            | `simulation` — виртуальная плата; `hardware` — реальная                    |
| `MERCURY_SERIAL_PORT`                | Порт платы; `auto` означает COM4 в Windows, `/dev/ttyUSB0` в Linux/macOS   |
| `MERCURY_API_HOST`                   | По умолчанию `127.0.0.1`; `0.0.0.0` открывает доступ из локальной сети     |
| `MERCURY_API_PORT`                   | Порт API и собранного интерфейса, по умолчанию `3001`                      |
| `MERCURY_WEB_PORT`                   | Порт Vite, по умолчанию `5173`                                             |
| `MERCURY_HARDWARE_MAX_TEMPERATURE_C` | Независимый предел аппаратного нагрева: 1–300 °C; в примере `.env` — 50 °C |
| `MERCURY_CONFIG_PATH`                | Путь к настройкам; по умолчанию корневой `config.json`                     |
| `MERCURY_DATABASE_PATH`              | База профилей; по умолчанию `data/mercury.sqlite`                          |
| `MERCURY_LOG_USB_MOUNT`              | Точка монтирования USB для истории и журналов, обычно `/media/flash`       |
| `MERCURY_PANEL_FULLSCREEN`           | `true` — полноэкранная панель Raspberry без курсора                        |
| `MERCURY_PANEL_SOFTWARE_RENDERING`   | `true` — программный рендеринг Electron                                    |
| `MERCURY_UPDATE_URL`                 | Адрес сервера обновлений; значение приведено в `.env.example`              |

На Raspberry порт задаётся явно, например `/dev/serial0` или `/dev/ttyS0`.
При `STARTING` сервер автоматически переводит плату в `WORKING`; при потере
связи выполняет переподключение. Состояние видно по индикатору верхней панели.

Модель печи и подключение **230/380 В** выбираются отдельно от определяемой
версии платы и сохраняются в `config.json`. Модель 301/401 не используется.

## Доступ к настройкам и профилям

- **PIN 3457** открывает обычные настройки.
- **PIN 34572** дополнительно показывает выбор модели и подключения, историю
  запусков и изменение эталонной частоты вентилятора. В правой панели процесса
  появляется `Δ max` — максимальное абсолютное отклонение за текущий запуск.
- Ключ в правой панели настроек или перезапуск сервера/печи закрывает доступ.
- Свич **«Объединять роль оператора и инженера»** включён по умолчанию и
  сохраняется в `config.json`. Если выключен, создание и изменение профилей
  доступны только после ввода PIN. Недоступные кнопки создания и редактирования
  скрыты; выбор и запуск готовых профилей остаются доступны.

Ограничения проверяются и интерфейсом, и сервером. Данные графика текущего запуска
доступны оператору без расширенного PIN; архивная история требует `34572`.

Температуры профиля ограничены диапазоном **0–280 °C**, время — **0–99999 с**
(первый участок начинается с 0, последующие имеют положительную длительность).
Числовые параметры профиля — целые. Повторы отключены либо заданы числом 1–20.

Предупреждения вентилятора срабатывают ниже 50% сохранённого эталона, а ниже
20% добавляется жёлтое мерцание при выполнении. В настройках пороги показаны
в Гц: например, при эталоне 50 Гц — 25 и 10 Гц. Из-за оборотов профиль не
останавливается. Свич предупреждений позволяет отключить эту реакцию.

Термозащита задаёт общий порог **285 °C**, для поддержания — **130 °C**;
при выключенном свиче пороги **300 и 150 °C**. Независимый предел `.env` и
защиты самой платы сохраняются. Свич звуков управляет предупреждением двери
и программными ошибками; звуки включения, завершения и аварийный звук платы
от него не зависят.

## Хранение данных

На Raspberry хранятся программа, конфигурация и профили. При установке из
универсального архива используются:

- программа — `/opt/mercury-v2/program`;
- настройки — `/home/pi/.config/mercury-v3/config.json`;
- профили и выбранный профиль — `/home/pi/.config/mercury-v3/profiles.sqlite`;
- служба пользователя — `mercury-v2`.

История температур, событий и технический журнал приложения пишутся **только
на смонтированный исправный USB**. При его отсутствии или отказе записи
пропускаются; резервной истории на SD и накопления отсчётов в RAM нет.
Поэтому без USB фактический график из истории может быть недоступен, хотя
управление печью продолжает работать.

При заполнении USB до 80% фоновая очистка удаляет старые данные приложения до
50%, насколько это возможно без удаления посторонних файлов и активных данных.
Подробности: [хранение и очистка USB](docs/usb-logging.md).

## Raspberry Pi и обновления

Для доступа из локальной сети установи `MERCURY_API_HOST=0.0.0.0` и открывай
`http://<IP-Raspberry>:3001`. Установка из универсального архива и прежняя
установка из исходников используют разные пути и имена служб — смотри
[инструкцию развёртывания](docs/raspberry-deployment.md).

Пакет обновления общий для всех моделей и подключений; индивидуальные настройки
и профили сохраняются. После `pnpm build` сборка на ПК выполняется командой:

```sh
python scripts/build-universal-release.py
```

Нужен подготовленный кеш ARM64 runtime `release/arm64-runtime.tar.gz`.
Файлы для сервера создаются в `release/publish`: архив версии,
`manifest.json`, `version` и `SHA256SUMS`. Сборка, отправка кода в Git и
публикация на сервер обновлений — отдельные действия. Кнопка «Обновить»
в настройках использует адрес `MERCURY_UPDATE_URL`.

## Проверки

```sh
pnpm typecheck
pnpm format:check
pnpm build
pnpm --filter @mercury/server test
node --test apps/web/tests/*.test.mjs
```

`pnpm check` выполняет проверку типов, форматирования и сборку, но не тесты.
Тесты запускаются после сборки. `dist`, `.env`, локальные базы и установочные
архивы не коммитятся. Перед фиксацией 3.1.5 прошли
[100 автоматических проверок](docs/test-results/release-3.1.5-2026-10-27.txt);
последующие исправления проверяются отдельно.

В режиме `simulation` нагрев, охлаждение и выходы моделируются виртуальной
платой. Её состояние доступно через `GET /api/controller/virtual-board`.
Это позволяет проверять управление без запуска реального нагрева.
