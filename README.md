# Mercury 3.4.11

ПО управления печами оплавления **Меркурий-300** и **Меркурий-400**.

[Руководство пользователя PDF для версии 3.4.11](output/pdf/Mercury-3.4.11-User-Manual.pdf).

В 3.4.11 описаны контракты прикладных модулей и критичных методов,
добавлено руководство разработчика и актуализирована инструкция калибровки.
Калибровка каждого датчика хранится отдельно от обновляемой программы.
Короткая пауза теперь сразу прерывает стабильную выдержку калибровки;
манифест обновления ограничен 16 КиБ при потоковом чтении.
Основная платформа — Raspberry Pi с сенсорным экраном: сервер управляет платой
печи, Electron показывает интерфейс встроенного экрана. Отдельная панель ПК
доступна в браузере по IP-адресу Raspberry в локальной сети.

Версия **3.4.11** включает отдельную панель ПК: обзор, таблицу профилей,
редактор с предпросмотром и настройки по PIN. В Electron сохранена компоновка
экрана печи; по отдельному запросу в обычных настройках открыта история запусков.
Браузерная сборка создаётся командой
`pnpm --filter @mercury/web build:pc` в `apps/web/pc-dist`; сервер выбирает её
для обычного браузера, сохраняя прежние файлы `apps/web/dist` для Electron.

## Возможности

- Панель ПК: обзор нескольких печей, обнаружение mDNS/DNS-SD и ручное добавление
  по локальному IP. Имя и описание хранятся в `config.json` каждой Raspberry;
  редактируются в настройках с соответствующим уровнем доступа.
- Проверка профиля перед запуском: датчик, пик, циклы, расчётное время и
  предупреждения о скорости нагрева/охлаждения для выбранной конфигурации.
- Дублирование, импорт/экспорт JSON и передача копий профилей между печами
  с проверкой совместимости получателя, без ввода PIN при проверке и передаче. Существующие профили не перезаписываются.
- Предупреждение о несохранённых изменениях и отмена правок в редакторе ПК.
  При потере связи показания помечаются устаревшими, команды блокируются;
  накопления и автоматического повтора команд нет.
- В браузере каждый запуск профиля требует PIN доступа; остановка доступна без PIN.
  Настройки сети доступны только в приложении на экране печи. История в веб-версии доступна всем;
  на экране печи — из настроек после обычного PIN, без расширенного кода.
- Мобильная панель: нижняя навигация с иконками, карточки профилей,
  закреплённое управление и оригинальная иконка для домашнего экрана.
  HTTPS и фоновые push-уведомления — следующий этап;
  [мобильная версия и установка](docs/mobile-2026-10-28.md).
- Создание, редактирование и выполнение температурных профилей, выбор датчика
  камеры или датчика на плате, до 20 циклов выполнения.
- График заданной и фактической температуры, пауза, продолжение и остановка.
  Выполнение идёт на сервере и не зависит от открытой страницы.
- Совместное регулирование ламп и ТЭНов, прогноз температуры и управление
  охлаждением. Измеренные характеристики относятся к новым платам:
  М301/220 В, М301/380 В, М401/220 В, М401/380 В.
  Старые М300 и М400 работают только от 220 В; чужие измеренные характеристики к ним не применяются.
- Поддержание 100 °C, индикация двери, элементов печи и связи с платой.
- При открытии двери во время профиля нагрев отключается и звучит предупреждение;
  после закрытия управление продолжается с попыткой догнать график.
- Два длинных сигнала при завершении в допуске ±4 °C, три — при выходе за допуск.
- Проверка элементов печи, настройка вентилятора, звуков и термозащиты.
- [Калибровка датчика камеры и датчика на плате](docs/calibration-2026-11-02.md) по внешнему термометру доступна только на встроенном экране печи; раздельные поправки сохраняются в отдельном файле вне программы и переживают обновления.
- Подключение к Wi-Fi через NetworkManager на Raspberry Pi.
- История запусков и технический журнал только на исправном USB-накопителе.
- Отдельный USB-файл наработки элементов `mercury-logs/element-runtime.json`:
  секунды включения ТЭНов, пар ламп и вентиляторов по конфигурациям.
  Подробности: [учёт наработки](docs/element-runtime.md).
- Виртуальная плата для разработки без оборудования.

На дисплее температуры округляются до целых; управление использует точные
значения. Выделение текста интерфейса отключено, поля ввода остаются редактируемыми.
После ошибки или перезапуска нагрев автоматически не возобновляется.

Результаты проверки браузерной функциональности на двух печах:
[завершение этапа ПК](docs/pc-completion-2026-10-28.md).

## Разработка и запуск

Нужны **Node.js 24** и **pnpm 11.25.0**. Команды выполняются из корня проекта.
Если pnpm не установлен: `npm install --global pnpm@11.25.0`.

Создай `.env` из [.env.example](.env.example):

```sh
cp .env.example .env
pnpm install --frozen-lockfile
pnpm dev
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.
`pnpm dev` запускает API, Vite и Electron. Для разработки только через браузер:

```sh
pnpm dev:web
```

Адреса по умолчанию:

- интерфейс разработки — `http://127.0.0.1:5173`;
- API — `http://127.0.0.1:8075/api/health`.

Vite перенаправляет `/api` на сервер. `Ctrl+C` останавливает группу процессов.
После изменения `.env` нужен перезапуск. `.env` не хранится в Git.

Для собранной версии:

```sh
pnpm build
pnpm start
```

Сервер отдаёт интерфейс и API на одном порту, по умолчанию `8075`.
Для запуска без Electron: `pnpm --filter @mercury/server start`.
Обычный `vite preview` не заменяет API-сервер.

## Конфигурация

| Переменная `.env`                    | Назначение                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------- |
| `MERCURY_CONTROLLER_MODE`            | `simulation` — виртуальная плата; `hardware` — реальная                    |
| `MERCURY_SERIAL_PORT`                | Порт платы; `auto` означает COM4 в Windows, `/dev/ttyUSB0` в Linux/macOS   |
| `MERCURY_API_HOST`                   | По умолчанию `127.0.0.1`; `0.0.0.0` открывает доступ из локальной сети     |
| `MERCURY_API_PORT`                   | Порт API и собранного интерфейса, по умолчанию `8075`                      |
| `MERCURY_WEB_PORT`                   | Порт Vite, по умолчанию `5173`                                             |
| `MERCURY_HARDWARE_MAX_TEMPERATURE_C` | Независимый предел аппаратного нагрева: 1–300 °C; в примере `.env` — 50 °C |
| `MERCURY_CONFIG_PATH`                | Путь к настройкам; по умолчанию корневой `config.json`                     |
| `MERCURY_DATABASE_PATH`              | База профилей; по умолчанию `data/mercury.sqlite`                          |
| `MERCURY_LOG_USB_MOUNT`              | Точка монтирования USB для истории и журналов, обычно `/media/flash`       |
| `MERCURY_PANEL_FULLSCREEN`           | `true` — полноэкранная панель Raspberry без курсора                        |
| `MERCURY_PANEL_SOFTWARE_RENDERING`   | `true` — программный рендеринг Electron                                    |
| `MERCURY_UPDATE_URL`                 | Адрес сервера обновлений; значение приведено в `.env.example`              |

На Raspberry порт задаётся явно, например `/dev/serial0` или `/dev/ttyS0`.
При `STARTING` сервер автоматически переводит плату в `WORKING`; при потере
связи выполняет переподключение. Состояние видно по индикатору верхней панели.

Выбираются размерная серия и фактическое подключение **220/380 В**.
Поколение платы определяется существующей логикой протокола: старая плата —
М300/М400, новая — М301/М401. Итого шесть конфигураций; 380 В для старой платы недоступны.
В `config.json` сохранены совместимые ключи серии `300`/`400` и однофазного
подключения `230`, чтобы сохранить настройки, измеренные характеристики и
калибровку уже испытанных новых плат. В интерфейсе однофазное подключение обозначено как 220 В.
[Таблица конфигураций и определение платы](docs/oven-model-identification.md).

## Доступ к настройкам и профилям

Старая программа мониторинга может читать состояние по `http://<IP>:3457/status` без PIN. На этом же порту доступны защищённые команды запуска JSON-профиля и остановки. Формат описан в [совместимости мониторинга](docs/legacy-monitoring-2026-10-29.md).

- **PIN оператора** (изначально `3457`) открывает обычные настройки, включая изменение эталонной частоты конвекции. Его можно изменить в настройках; значение сохраняется в виде хеша.
- **Расширенный доступ** дополнительно показывает выбор модели и подключения и сервисные действия. В правой панели процесса
  появляется `Δ max` — максимальное абсолютное отклонение за текущий запуск.
- Доступ отдельный для каждого экземпляра приложения/вкладки: разблокировка и блокировка одного устройства не меняет другие. Обновление страницы, перезапуск приложения/печи и смена PIN блокируют доступ.
- В мобильной версии ключ блокировки находится в верхней панели, кнопка запуска — под графиком, оповещения — в меню «Ещё».
- Восстановление PIN оператора: на экране печи открыть ввод PIN, нажать физическую кнопку выключения и в течение 15 секунд ввести `88888888`. PIN вернётся к `3457`, прозвучит один длинный сигнал, затем печь выключится. Без кода печь просто выключится по истечении окна.
- По расширенному PIN доступен сброс моточасов с подтверждением. На исправном USB счётчики обновляются; рядом с конфигурацией хранится резервная копия при включении, а при отказе USB она используется только для отображения.
- Свич **«Объединять роль оператора и инженера»** включён по умолчанию и
  сохраняется в `config.json`. Если выключен, создание и изменение профилей
  доступны только после ввода PIN. Недоступные кнопки создания и редактирования
  скрыты; выбор и запуск готовых профилей остаются доступны.

Ограничения проверяются и интерфейсом, и сервером. Данные графика текущего запуска
доступны оператору без расширенного PIN; история в браузере публична, на экране печи доступна после обычного PIN.

Температуры профиля ограничены диапазоном **0–280 °C**, время — **0–99999 с**
(первый участок начинается с 0, последующие имеют положительную длительность).
Числовые параметры профиля — целые. Повторы отключены либо заданы числом 1–20.

Предупреждения вентилятора срабатывают ниже 50% сохранённого эталона, а ниже
20% добавляется жёлтое мерцание при выполнении. В настройках пороги показаны
в Гц: например, при эталоне 50 Гц — 25 и 10 Гц. Из-за оборотов профиль не
останавливается. Свич предупреждений позволяет отключить эту реакцию.

Термозащита задаёт общий порог **285 °C**, для поддержания — **130 °C**;
при выключенном свиче пороги **300 и 150 °C**. Независимый предел `.env` и
защиты самой платы сохраняются. Свич звуков управляет предупреждением двери
и программными ошибками; звуки включения, завершения и аварийный звук платы
от него не зависят.

## Хранение данных

На Raspberry хранятся программа, конфигурация и профили. При установке из
универсального архива используются:

- программа — `/opt/mercury-v2/program`;
- настройки — `/home/pi/.config/mercury-v3/config.json`;
- профили и выбранный профиль — `/home/pi/.config/mercury-v3/profiles.sqlite`;
- служба пользователя — `mercury-v2`.

История температур, событий и технический журнал приложения пишутся **только
на смонтированный исправный USB**. При его отсутствии или отказе записи
пропускаются; резервной истории на SD и накопления отсчётов в RAM нет.
Поэтому без USB фактический график из истории может быть недоступен, хотя
управление печью продолжает работать.

При заполнении USB до 80% фоновая очистка удаляет старые данные приложения до
50%, насколько это возможно без удаления посторонних файлов и активных данных.
Подробности: [хранение и очистка USB](docs/usb-logging.md).

## Raspberry Pi и обновления

Для доступа из локальной сети установи `MERCURY_API_HOST=0.0.0.0` и открывай
`http://<IP-Raspberry>:8075`. Установка из универсального архива и прежняя
установка из исходников используют разные пути и имена служб — смотри
[инструкцию развёртывания](docs/raspberry-deployment.md).

Пакет обновления общий для всех моделей и подключений; индивидуальные настройки
и профили сохраняются. После `pnpm build` сборка на ПК выполняется командой:

```sh
python scripts/build-universal-release.py
```

Нужен подготовленный кеш ARM64 runtime `release/arm64-runtime.tar.gz`.
Файлы для сервера создаются в `release/publish`: архив версии,
`manifest.json`, `version` и `SHA256SUMS`. Сборка, отправка кода в Git и
публикация на сервер обновлений — отдельные действия. Кнопка «Обновить»
в настройках использует адрес `MERCURY_UPDATE_URL`.

Проверка версии не начинает скачивание. Перед загрузкой требуется отдельное
подтверждение с номером версии. Во время скачивания и установки все открытые
интерфейсы показывают блокирующий экран ожидания; сервер отклоняет изменения.
После скачивания блокировка снимается, установка запускается отдельно.
[Правила доступа и обновления](docs/operator-update-policy-2026-11-02.md).

## Проверки

```sh
pnpm typecheck
pnpm format:check
pnpm build
pnpm --filter @mercury/server test
node --test apps/web/tests/*.test.mjs
```

`pnpm check` выполняет проверку типов, форматирования и сборку, но не тесты.
Тесты запускаются после сборки. `dist`, `.env`, локальные базы и установочные
архивы не коммитятся. После изменения доступа и обновления для 3.4.11 выполнено 175 автоматических тестов:
174 успешно, один Linux-тест пропущен на Windows, ошибок нет.
[Полный прогон](docs/test-results/operator-update-full-2026-11-02.txt).
Дополнительно прошли две проверки блокировки интерфейса при загрузке, обрыве сети и перезапуске установщика.
[Полный отчёт](docs/test-results/release-3.4.11-2026-11-02.md).

В режиме `simulation` нагрев, охлаждение и выходы моделируются виртуальной
платой. Её состояние доступно через `GET /api/controller/virtual-board`.
Это позволяет проверять управление без запуска реального нагрева.

## Подготовка HTTPS и уведомлений

Код Web Push и необязательного HTTPS готов к настройке. Подписки включаются
по PIN на каждом телефоне; события: запуск, циклы, завершение, остановка,
ошибка и потеря связи с платой. До выбора доверенного HTTPS-адреса функция
выключена. На печах пока остаётся мобильная версия без активированных push.
Порядок включения и проверки: [HTTPS и Web Push](docs/push-https-2026-10-29.md).

## Локальные оповещения

На обеих печах включены сообщения внутри активной веб-панели, без интернета
и HTTPS: запуск, завершение, остановка, ошибки и потеря связи с платой.
На телефоне настройка находится в «Ещё» → «Уведомления»; звук разрешается
нажатием кнопки. Скрытая/заблокированная панель не получает фоновые оповещения.
[Подробности и проверки](docs/active-notifications-2026-10-29.md).
